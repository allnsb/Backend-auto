# P4-b 图片与语音附件

更新时间：2026-10-31。本文记录 HTTP 0.8.0／第十一项迁移。文字会话、论坛、频道、写预算和 Outbox 分区保持原有行为。自定义表情、已读回执、频道复杂权限、病毒扫描队列、编辑／删除、保留期限和管理员访问不在本刀。

## 已确认的产品决定

1. 会话消息可以带图片或语音。没有附件时正文仍不能为空白。有附件时正文可以为空，也可以同时有文字。
2. 对象放在 Cloudflare R2。第一刀由 API 收齐字节再同步 `PutObject`。下载先检查会话成员，再 302 到短时预签名 GET。预签名 URL 是不记名凭证，默认 60 秒，配置上限 5 分钟。
3. `BlobStore` 只有 `Put`、`PresignGet` 和 `Delete`。以后换成预签名 PUT 时，消息绑定和成员检查不必重写。
4. 发送只绑定：上传者本人、同一会话、`ready`、尚未挂到任何消息上的附件。不满足时返回 422／`attachment_rejected`，不区分“不存在”和“别人的”。
5. 非成员、已退出成员和已解散的会话下载都是 404。附件还没挂到消息上时，只有上传者本人可以取预签名 URL；其他成员要等消息发出。
6. 论坛和频道消息仍必须有正文。空正文只允许出现在带附件的会话消息上。

## 默认限制

配置只能把限制调低，不能超过数据库天花板。未设置环境变量时用默认值。

| 项 | 默认 | 天花板 | 环境变量 |
|---|---|---|---|
| 单个对象 | 10MiB | 10MiB | `ODYSSEIA_ATTACHMENT_MAX_BYTES` |
| 图片边长 | 8192 | 32768 | `ODYSSEIA_ATTACHMENT_MAX_EDGE` |
| 图片像素 | 16777216 | 67108864 | `ODYSSEIA_ATTACHMENT_MAX_PIXELS` |
| 语音时长 | 300000ms | 300000ms | `ODYSSEIA_ATTACHMENT_MAX_VOICE_MS` |
| 每用户每分钟上传次数 | 10 | 60 | `ODYSSEIA_ATTACHMENT_UPLOADS_PER_MINUTE` |
| 每用户已存字节 | 100MiB | 1GiB | `ODYSSEIA_ATTACHMENT_USER_QUOTA_BYTES` |
| 预签名有效期 | 60s | 5m | `ODYSSEIA_ATTACHMENT_PRESIGN_TTL` |
| 每条消息附件数 | 4 | 4 | `ODYSSEIA_ATTACHMENT_MAX_PER_MESSAGE` |

图片允许 `image/jpeg`、`image/png`、`image/webp`、`image/gif`。语音允许 `audio/webm;codecs=opus`、`audio/mp4`、`audio/ogg`（Ogg 里的 Opus 或 Vorbis）。SVG、HTML 和其余类型返回 415／`unsupported_media_type`。超过字节上限返回 413／`body_too_large`。超过已存配额返回 413／`upload_quota_exceeded`。超过每分钟次数返回 429／`upload_rate_exceeded`，`Retry-After: 60`。

客户端报的 `duration_ms` 只用于语音。图片带这个字段会被拒绝。容器里能读出时长时，入库的是容器时长，并且它必须和客户端申报相差不超过 2 秒或 10%（取较大者），同时不超过上限。WebM 常常没有 Duration 元素；这时才采用客户端申报，并要求文件至少有 `max(32, 申报毫秒/125)` 字节，避免很小的文件声称有 5 分钟。服务端不解码音频采样，伪造的 granule 或 mvhd 可以在 10MiB 以内少报时长。

## 数据与迁移

第十一项迁移 `00011_attachments.sql`：

- `messages.body` 的检查从 `octet_length BETWEEN 1 AND 32768` 放宽到 `BETWEEN 0 AND 32768`。这张表同时给论坛、频道和会话用。
- 延迟约束触发器 `messages_text_or_attachment`：正文至少 1 字节时立刻返回，论坛和频道的普通插入不会再查流类型。正文为空时，只有 `kind = conversation` 且同一事务里已经挂上 `message_attachments` 才允许提交。因此空正文的论坛／频道行会在提交时失败。已有行本来就有正文，迁移不改写它们。
- 删除最后一条附件时，若正文为空，另一条延迟触发器同样拒绝。运行身份没有 DELETE 权限；这是给以后的维护动作留的不变量。
- `attachments`：上传者、会话、种类、允许的 content type、字节、宽高或时长、服务端对象键、SHA-256、`status = ready`。对象键形状是 `conversations/<会话 UUID>/<附件 UUID>`。
- `message_attachments`：一条附件只能挂一次，一条消息里位置 0 到 3。
- 不改 Outbox，不要求排空。事件仍走 `conversation.message.created`，载荷里多了附件元数据，没有预签名 URL。

回滚在存在附件行或空正文时直接失败，不删数据。P3 的迁移往返测试先卸下第十一项，再卸下第十项和第八项。

运行身份在原有授权之外需要：

```sql
GRANT SELECT, INSERT, UPDATE ON odysseia.attachments TO odysseia_runtime;
GRANT SELECT, INSERT ON odysseia.message_attachments TO odysseia_runtime;
```

`UPDATE` 不写列。PostgreSQL 要求 `SELECT … FOR UPDATE` 具备 UPDATE 权限，绑定附件时用它锁住行。列表和幂等重放要 `SELECT message_attachments`。没有 DELETE。配额和频率在插入前对 `hashtext('odysseia-attachment-upload')` 加事务级咨询锁，所以多个 API 进程共用同一计数，不是每进程一份内存限额。上传不占用论坛写预算；R2 写入发生在短事务之外，失败插入会删除对象。删除失败时对象会变成没有数据库行的残留，本刀没有清扫任务。

## API

OpenAPI `info.version` 为 0.8.0。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/v1/conversations/{id}/attachments` | `multipart/form-data`，字段 `file`，语音另加 `duration_ms`。201 返回附件元数据。 |
| GET | `/v1/conversations/{id}/attachments/{attachment_id}` | 成员检查后 302。响应带 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。 |
| POST | `/v1/conversations/{id}/messages` | `attachment_ids` 可选。空 `body` 仅在有附件时合法。幂等摘要包含附件 ID；没有附件时 JSON 与文字刀相同。 |

对象响应上的 `Content-Type` 是检测后的类型，`Content-Disposition` 使用服务端文件名（`image.jpg`、`voice.webm` 等），`Cache-Control` 是 `private, no-store`。S3 兼容接口签不出 `X-Content-Type-Options`，所以 nosniff 只出现在 API 的 302 上。对象类型来自允许列表，不来自客户端声明。

其它接口仍是 10 秒读超时和 10 秒处理时限。上传单独把连接的读、写截止时间以及该请求的 context 放到 2 分钟，避免移动网络上的 10MiB 被 10 秒切断。HTTP 入口做一次容器解析和元数据剥离；入库前只复核允许列表、大小、尺寸或时长，以及摘要是否对得上字节。R2 的 SDK 只出现在 `blob` 包和进程装配处。JPEG 只保留一个 Orientation 标签，宽高按这个标签换成显示尺寸。分片 MP4 的 mvhd 为 0 时，mehd 用电影 timescale，trun 用音轨 mdhd 的 timescale；都没有正时长才用客户端申报和最小字节检查。udta／©xyz 换成等长 free，不挪动 stco 和 tfhd 偏移。

## 与设计的偏差

- 迁移号是 **00011**。00010 已由文字会话占用。
- 存储的语音时长优先用容器时钟。WebM 没有 Duration，或分片 MP4 的 mvhd／mehd／trun 都给不出正时长时，才用客户端申报，并且要过最小字节检查。
- JPEG 会留下一个只含 Orientation 的 EXIF，宽高是按该标签转过的显示尺寸。GIF 去掉注释和 XMP，动画数据不动。MP4 把 udta／©xyz 换成等长 free，WebM 去掉 Tags。不整图重编码。不认识的私有段会留下。
- 每条消息最多 4 个附件，由配置和 `message_attachments.position < 4` 一起卡住。
- 未绑定的附件只有上传者能下载。这比“任何成员拿到 UUID 就能下”更窄。
- 频率和配额按上传者的已存行计算，包含还没发出去的对象。没有删除接口，也没有过期清扫。
- 病毒扫描、自定义表情、已读回执、作品文件和预签名 PUT 都没做。
