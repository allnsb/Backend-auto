# P4-b 图片与语音附件

更新时间：2026-10-31。本文记录 HTTP 0.8.0／第十一项迁移的图片与语音，以及 HTTP 0.8.1／第十二项迁移的约 7 天清扫。文字会话、论坛、频道、写预算和 Outbox 分区保持原有行为。自定义表情、已读回执、频道复杂权限、病毒扫描队列、编辑／删除和管理员访问不在本刀。客户端缓存不在清扫范围。

## 已确认的产品决定

1. 会话消息可以带图片或语音。没有附件时正文仍不能为空白。有附件时正文可以为空，也可以同时有文字。
2. 对象放在 Cloudflare R2。第一刀由 API 收齐字节再同步 `PutObject`。下载先检查会话成员，再 302 到短时预签名 GET。预签名 URL 是不记名凭证，默认 60 秒，配置上限 5 分钟。
3. `BlobStore` 只有 `Put`、`PresignGet` 和 `Delete`。以后换成预签名 PUT 时，消息绑定和成员检查不必重写。
4. 发送只绑定：上传者本人、同一会话、`ready`、尚未挂到任何消息上的附件。不满足时返回 422／`attachment_rejected`，不区分“不存在”和“别人的”。
5. 非成员、已退出成员和已解散的会话下载都是 404。附件还没挂到消息上时，只有上传者本人可以取预签名 URL；其他成员要等消息发出。
6. 论坛和频道消息仍必须有正文。空正文只允许出现在带附件的会话消息上。
7. 会话附件不无限期堆在对象存储里。默认从 `attachments.created_at` 起保留约 7 天，之后可以删对象。文字消息本身不删。

## 保留与容量

时钟用上传时间，已挂到消息上的和还没发出去的一样。默认 7 天（168 小时）。`ODYSSEIA_ATTACHMENT_RETENTION` 未设置即 `168h`。这是 Go 的 duration，没有 `d` 单位，可取 `1h` 到 `8784h`。API 进程不读这个变量，也不删行、不删对象。

清扫是独立命令 `attachment-sweep`，跑完一批就退出，由外部定时重复调用。不放进 API 进程，避免多个 API 副本同时扫，也避免和请求处理绑在一起。重复执行是安全的：对象已经不在时 `Delete` 仍成功；未绑定的行删掉之后不会再被选中；已绑定的行标成 `expired` 之后也不再被选中。

一条命令会把当前已经超过保留期的 `ready` 行扫完。数据库按 `created_at, id` 一批最多 100 行，用 `FOR UPDATE SKIP LOCKED` 锁住，再经 `BlobStore.Delete` 删对象，然后在同一事务里写库。比较用的是数据库时钟，`created_at <= transaction_timestamp() - 保留期`。

1. 没挂到任何消息上的附件：删 R2 对象，再删 `attachments` 行。
2. 已经挂到消息上的：删 R2 对象，把 `status` 写成 `expired` 并记下 `expired_at`，**留下** `message_attachments`。空正文的消息如果拆掉最后一条附件，现有延迟触发器会拒绝提交，所以不能靠删链接来“清空”。历史里仍能看到这条附件，响应带 `expired: true`；下载不再签发 URL，和未知 ID 一样是 404。
3. 文字正文保持不动。

对象删除失败的行保持 `ready`，命令以非零退出，下一轮再试。已经删成的对象和已经写上的行会先提交。某个对象在写库之前就没了（例如上次删完对象后进程停了）时，下一轮的 `Delete` 仍成功，然后补上删行或标过期。

过期行不再计入「每用户已存字节」。上传次数仍只数最近一分钟里 `ready` 的行。运行身份需要在原有授权之外增加 `attachments` 的 `DELETE`，并且仍然没有 `message_attachments` 的 `DELETE`，这样命令用 API 同一个库账号即可，写错 SQL 也拆不掉空正文上的链接。迁移账号能删链接，所以清扫不用它。

```text
# 先迁移，再给运行身份补上这一句（已有 SELECT/INSERT/UPDATE 不用重授）
GRANT DELETE ON odysseia.attachments TO odysseia_runtime;

# 与 API 相同的 ODYSSEIA_DATABASE_URL 和 ODYSSEIA_R2_*。
# 保留期可省略，省略就是 168h。
go run ./cmd/attachment-sweep
```

建议至少每天跑一次，每小时一次即可。日志只有删除计数和保留期，不写对象键或密钥。

桶上的生命周期是兜底，不是唯一手段。对象键前缀是 `conversations/`。建议规则：该前缀满 **8** 天删除，比应用的 7 天晚一天，给清扫留出标记过期的窗口。R2 的删除通常在到期后 24 小时内发生，`DeleteObject` 不计费。清扫命令已经能把库记录标成过期，这条规则现在可以打开；请先把命令排进定时任务再打开。清扫停摆超过一天时，生命周期仍会删掉对象，库里可能暂时留下 `ready` 行并 302 到已经没了的对象，下一轮清扫会把这些行标成过期。没有库行的残留对象（插入失败且当时删对象也失败）只有生命周期能收掉，清扫只看表。

仪表盘：R2 → 桶 → Settings → Object Lifecycle Rules → Add rule，前缀 `conversations/`，Expire objects after **8** days。Wrangler（[命令说明](https://developers.cloudflare.com/r2/reference/wrangler-commands/)，2026-10 核对）：

```text
npx wrangler r2 bucket lifecycle add <BUCKET> expire-conversation-attachments conversations/ --expire-days 8
```

等价的 S3 规则是 `Filter.Prefix = conversations/`、`Expiration.Days = 8`、`Status = Enabled`。不要把这批对象转 Infrequent Access。

Infrequent Access 不适合这 7 天。它有 30 天最短存储，提前删除仍按 30 天计费，而且读还要数据取回费。会话附件继续放 Standard。

容量紧时的顺序，价格按 [R2 定价](https://developers.cloudflare.com/r2/pricing/)（页内标注 2026-10-30）：

| 做法 | 结果 | 取舍 |
|---|---|---|
| 维持 R2 Standard 免费额度 | 每月 10 GB-month、100 万次 Class A、1000 万次 Class B，出站免费 | 开发默认。图片和语音很容易超过 10 GB-month |
| R2 付费加量 | Standard 存储 $0.015 / GB-month，出站仍免费。`BlobStore` 和端点都不用改 | **推荐的下一步。** 容量不够时先加这份账单，不换存储 |
| 生命周期删过期对象 | 前缀 `conversations/` 满 8 天删除，和上面的 7 天产品期对齐 | 清扫命令已经落地。先把 `attachment-sweep` 排进定时任务，再打开这条桶规则 |
| 换另一个 S3 兼容服务 | 只改 `ODYSSEIA_R2_ENDPOINT` 和密钥 | 仅当 R2 账号或区域不可用。要先看清出站费；带出站费的存储不适合成员反复下载 |
| 自建 MinIO 一类 | 仍是 S3 API | 磁盘、备份和加密都要自己管，不作为默认 |

正式存放目标仍是 Cloudflare R2。不因为免费额度吃紧就改存储接口。

## 默认限制

配置只能把限制调低，不能超过数据库天花板。未设置环境变量时用默认值。

| 项 | 默认 | 天花板 | 环境变量 |
|---|---|---|---|
| 单个对象 | 10MiB | 10MiB | `ODYSSEIA_ATTACHMENT_MAX_BYTES` |
| 图片边长 | 8192 | 32768 | `ODYSSEIA_ATTACHMENT_MAX_EDGE` |
| 图片像素 | 16777216 | 67108864 | `ODYSSEIA_ATTACHMENT_MAX_PIXELS` |
| 语音时长 | 300000ms | 300000ms | `ODYSSEIA_ATTACHMENT_MAX_VOICE_MS` |
| 每用户每分钟上传次数 | 10 | 60 | `ODYSSEIA_ATTACHMENT_UPLOADS_PER_MINUTE` |
| 每用户已存字节 | 100MiB | 1GiB | `ODYSSEIA_ATTACHMENT_USER_QUOTA_BYTES` |
| 预签名有效期 | 60s | 5m | `ODYSSEIA_ATTACHMENT_PRESIGN_TTL` |
| 每条消息附件数 | 4 | 4 | `ODYSSEIA_ATTACHMENT_MAX_PER_MESSAGE` |

图片允许 `image/jpeg`、`image/png`、`image/webp`、`image/gif`。语音允许 `audio/webm;codecs=opus`、`audio/mp4`、`audio/ogg`（Ogg 里的 Opus 或 Vorbis）。SVG、HTML 和其余类型返回 415／`unsupported_media_type`。超过字节上限返回 413／`body_too_large`。超过已存配额返回 413／`upload_quota_exceeded`。超过每分钟次数返回 429／`upload_rate_exceeded`，`Retry-After: 60`。

客户端报的 `duration_ms` 只用于语音。图片带这个字段会被拒绝。容器里能读出时长时，入库的是容器时长，并且它必须和客户端申报相差不超过 2 秒或 10%（取较大者），同时不超过上限。WebM 常常没有 Duration 元素；这时才采用客户端申报，并要求文件至少有 `max(32, 申报毫秒/125)` 字节，避免很小的文件声称有 5 分钟。服务端不解码音频采样，伪造的 granule 或 mvhd 可以在 10MiB 以内少报时长。

## 数据与迁移

第十一项迁移 `00011_attachments.sql`：

- `messages.body` 的检查从 `octet_length BETWEEN 1 AND 32768` 放宽到 `BETWEEN 0 AND 32768`。这张表同时给论坛、频道和会话用。
- 延迟约束触发器 `messages_text_or_attachment`：正文至少 1 字节时立刻返回，论坛和频道的普通插入不会再查流类型。正文为空时，只有 `kind = conversation` 且同一事务里已经挂上 `message_attachments` 才允许提交。因此空正文的论坛／频道行会在提交时失败。已有行本来就有正文，迁移不改写它们。
- 删除最后一条附件时，若正文为空，另一条延迟触发器同样拒绝。运行身份没有 DELETE 权限；这是给以后的维护动作留的不变量。
- `attachments`：上传者、会话、种类、允许的 content type、字节、宽高或时长、服务端对象键、SHA-256、`status = ready`。对象键形状是 `conversations/<会话 UUID>/<附件 UUID>`。
- `message_attachments`：一条附件只能挂一次，一条消息里位置 0 到 3。
- 不改 Outbox，不要求排空。事件仍走 `conversation.message.created`，载荷里多了附件元数据，没有预签名 URL。

回滚在存在附件行或空正文时直接失败，不删数据。P3 的迁移往返测试先卸下第十一项，再卸下第十项和第八项。

第十二项迁移 `00012_attachment_expiry.sql` 只改 `attachments`：`status` 可以是 `ready` 或 `expired`，`expired` 必须带 `expired_at`，`ready` 的 `expired_at` 必须为空。另有部分索引 `(created_at, id) WHERE status = 'ready'`，给定时清扫用。不改消息正文、不改 `message_attachments`、不改 Outbox，不要求排空。存在 `expired` 行时回滚直接失败。

运行身份在原有授权之外需要：

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON odysseia.attachments TO odysseia_runtime;
GRANT SELECT, INSERT ON odysseia.message_attachments TO odysseia_runtime;
```

`DELETE` 只给 `attachments`，给第十二项的清扫命令用。`message_attachments` 仍然没有 `DELETE`。

`UPDATE` 不写列。PostgreSQL 要求 `SELECT … FOR UPDATE` 具备 UPDATE 权限，绑定附件时用它锁住行。列表和幂等重放要 `SELECT message_attachments`。没有 DELETE。配额和频率在插入前对 `hashtext('odysseia-attachment-upload')` 加事务级咨询锁，所以多个 API 进程共用同一计数，不是每进程一份内存限额。上传不占用论坛写预算；R2 写入发生在短事务之外，失败插入会删除对象。上传插入失败且随后的对象删除也失败时，会留下没有数据库行的对象；清扫只处理表里的行，这种残留靠 `conversations/` 的 8 天生命周期收掉。

## API

OpenAPI `info.version` 为 0.8.1。0.8.0 是图片与语音上传；0.8.1 给附件增加可选字段 `expired`，并写明过期后的下载是 404。没有 `expired` 的响应和 0.8.0 相同。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/v1/conversations/{id}/attachments` | `multipart/form-data`，字段 `file`，语音另加 `duration_ms`。201 返回附件元数据。 |
| GET | `/v1/conversations/{id}/attachments/{attachment_id}` | 成员检查后 302。响应带 `Cache-Control: no-store` 和 `X-Content-Type-Options: nosniff`。 |
| POST | `/v1/conversations/{id}/messages` | `attachment_ids` 可选。空 `body` 仅在有附件时合法。幂等摘要包含附件 ID；没有附件时 JSON 与文字刀相同。 |

对象响应上的 `Content-Type` 是检测后的类型，`Content-Disposition` 使用服务端文件名（`image.jpg`、`voice.webm` 等），`Cache-Control` 是 `private, no-store`。S3 兼容接口签不出 `X-Content-Type-Options`，所以 nosniff 只出现在 API 的 302 上。对象类型来自允许列表，不来自客户端声明。

其它接口仍是 10 秒读超时和 10 秒处理时限。上传单独把连接的读、写截止时间以及该请求的 context 放到 2 分钟，避免移动网络上的 10MiB 被 10 秒切断。HTTP 入口做一次容器解析和元数据剥离；入库前只复核允许列表、大小、尺寸或时长，以及摘要是否对得上字节。R2 的 SDK 只出现在 `blob` 包和进程装配处。JPEG 只保留一个 Orientation 标签，宽高按这个标签换成显示尺寸。分片 MP4 的 mvhd 为 0 时，mehd 用电影 timescale，trun 用音轨 mdhd 的 timescale；都没有正时长才用客户端申报和最小字节检查。udta／©xyz 换成等长 free，不挪动 stco 和 tfhd 偏移。

## 与设计的偏差

- 迁移号是 **00011**。00010 已由文字会话占用。
- 存储的语音时长优先用容器时钟。WebM 没有 Duration，或分片 MP4 的 mvhd／mehd／trun 都给不出正时长时，才用客户端申报，并且要过最小字节检查。
- JPEG 会留下一个只含 Orientation 的 EXIF，宽高是按该标签转过的显示尺寸。GIF 去掉注释和 XMP，动画数据不动。MP4 把 udta／©xyz 换成等长 free，WebM 去掉 Tags。不整图重编码。不认识的私有段会留下。
- 每条消息最多 4 个附件，由配置和 `message_attachments.position < 4` 一起卡住。
- 未绑定的附件只有上传者能下载。这比“任何成员拿到 UUID 就能下”更窄。
- 频率和配额按上传者仍为 `ready` 的行计算，包含还没发出去的对象。过期行不占已存字节。没有给用户的删除接口；过期由 `attachment-sweep` 处理。
- 病毒扫描、自定义表情、已读回执、作品文件和预签名 PUT 都没做。
- 空的或过短的 `tkhd`，以及版本字节不是 0 或 1 的 `tkhd`，在读取前按长度拒绝，`Inspect` 返回 `ErrCorrupt`（HTTP 422／`invalid_input`）。登录用户重复上传这类文件不会再把 API 进程打成 panic。
