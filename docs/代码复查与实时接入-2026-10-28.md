## 既有代码复查

检查范围覆盖进程／HTTPS、输入边界、JWT／JWKS、数据库 TLS、用户映射、论坛事务／幂等、成员读取、引用外键、分页、事件编码、维护命令与隔离脚本。旧 NodeBB／IM 项目未改动。

| 发现 | 修复与证据 |
|---|---|
| 请求上下文的截止时间不能中止阻塞中的请求体读取，原服务器缺少 ReadTimeout。慢速已连接客户端可能持续占用处理协程。 | 使用真实 TLS 连接发送未完成请求体，原版本在上下文已取消后仍不退出，新增测试先失败。服务器增加 10 秒读取时限，读取超时映射为 408/request_timeout；同一测试验证处理退出及实际 408 响应，修复后通过。 |
| 请求头仍使用 Go 默认较大预算，与当前 16 KiB 令牌限制不匹配。 | MaxHeaderBytes 设置为 32 KiB；64 KiB 请求头原来进入健康接口返回 204，修复后由服务器拒绝为 431。Go 自身读取缓冲留量仍适用。 |

事务／权限审查未在当前范围复现新的越权或重复写入；真实 PostgreSQL 回归保留作者来源、成员拒绝、撤销后新请求、12 路幂等、8 路顺序、引用／层级约束、页间插入与 outbox 失败回滚检查。它不是零漏洞保证，也不替代真实 IdP、完整角色、容量或生产隐私验收。

使用官方 govulncheck v1.9.0、Go 1.27.3，先在既有 integration 调用图上扫描，再对新增 SDK 后包含测试与 integration,realtime 标签的完整调用图重扫，均返回 No vulnerabilities found。数据库来自 https://vuln.go.dev，更新时间为 2026-10-27 21:16:18 UTC；工具和缓存留在忽略的 runtime/backend。此结论是当时已知漏洞扫描，不是全部安全审计，也不覆盖外部 Centrifugo 可执行文件的完整软件供应链。Go 官方下载元数据同日确认 1.27.3 为稳定发行。

## 实际接通与验证

API 新增三个 bodyless POST：连接凭据、论坛频道凭据、帖子频道凭据。复用可信 JWT 身份和 GetForum／GetTopic 授权读取；不接受客户端自选用户或频道。外部认证 exp 单独随 Authentication／Actor 传递；实时凭据 exp 不超过原认证和 60 秒上限，连接／频道各使用独立随机密钥。API 失去外部认证或当前成员资格后不能续签。

测试运行官方原生 Centrifugo 子进程，消费者使用独立数据库身份和 verify-full；只授予 outbox SELECT／DELETE，不授予消息表或成员写入。官方 Go SDK 和 Gorilla 仅用于集成测试，go list 确认不进入 API 的构建依赖。运行配置、证书、随机秘密和日志留在受限且忽略的 runtime 目录，旧项目未改动。

| 已通过场景 | 实际证据 |
|---|---|
| 事务消息到真实 WSS | HTTPS 创建帖子／回复，原生消费者删除待发布记录，SDK 接收版本事件，消息 ID 与持久化响应相同。 |
| 短断线恢复 | SDK Disconnect／Connect，检查 WasRecovering 与 Recovered，收到断线期间提交的同一消息。 |
| 超出恢复窗口 | 测试缓存仅两条，离线提交三条；SDK 报告无法完整恢复，再以授权 HTTPS 历史加载取得全部缺失 ID。 |
| 订阅边界 | 他人连接不能使用 Alice 的频道 JWT；仅有连接 JWT 不能订阅；客户端直接 publish 被拒绝。 |
| 凭据端点 | 200、400、401、404 实际响应对照 OpenAPI，检查 no-store；自选频道／用户正文被拒绝，撤销成员后论坛和帖子续签均拒绝。 |
| 服务端到期处理 | 原始 WSS 客户端忽略刷新，订阅 ACK 明确 expires／TTL；两秒测试凭据到期后服务端按过期原因取消订阅或关闭连接，普通读超时不算通过。 |

调试时真实测试先暴露了过期检查使用周期调度：只缩短过期宽限仍不能在短测试窗口关闭，核对固定源码后把夹具 presence_update_interval 也设为一秒；保留严格断言，不将超时改成成功。模板使用相同设置，这是一项未经过容量评估的本机默认。不是在业务代码中添加条件补丁。

默认 go test、真实 integration,realtime 测试、带相同标签的 go vet、go mod verify、四个命令的 Linux／amd64 交叉构建通过；未在 Linux 运行或部署。独立 PostgreSQL 容器／网络和 Centrifugo 子进程均已清理，受限运行文件仍保留。完整重跑命令与前端接入见 [实时说明](../backend/deploy/realtime/README.md)，官方来源／许可／借鉴范围见 [复用记录](../../research/realtime-reuse-2026-10-28.md)。

## 仍有的工程边界

- 这是短期凭据租约，成员移除后旧凭据直到 exp 加关闭宽限／周期检查仍可能有效；没有即时踢出或已定义的撤销 SLA。即时撤权及成员变更路径是 P2 下一项，A07 不计完成。
- 单进程内存恢复缓存不是持久历史。消费崩溃／重复／乱序、进程重启、多节点、Valkey、积压和三万在线容量还未验收，不能从本机投递推导生产保证。
- WSS 客户端验证 CA／主机名并要求 TLS 1.3；Centrifugo 原生 6.10.2 的 TLS 配置最低为 1.2。未宣称原生服务拒绝 1.2，生产严格 1.3 网关和网络隔离待验证；源码证据见实时复用记录。
- 真实 IdP、存储／备份加密、密钥轮换／恢复及管理员审计尚未实施或验收，只使用合成数据。

本轮没有改变业务产品规则。更换实时供应商主要涉及 realtime 凭据签发、postgres 的事件格式适配和入口装配；forum／message 模型无新增实时 SDK 依赖。移除实时路由不影响独立身份和论坛验证，没有为了这一步建立空服务层、每表接口或请求内嵌套扫描。
