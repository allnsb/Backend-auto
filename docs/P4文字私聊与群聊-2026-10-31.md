# P4-a 文字私聊与群聊

更新时间：2026-10-31。本文记录 HTTP 0.7.0／第十项迁移的文字会话切片。帖子、固定频道、写预算和协作面保持原有行为。自定义表情、复杂频道权限、已读回执、编辑／删除、保留期限和管理员访问不在本刀。图片和语音在随后的 [P4-b](P4图片与语音附件-2026-10-31.md) 里实现，不改写本刀当时的文字范围。

## 已确认的产品决定

1. 发起私聊时，双方必须至少同属一个论坛。查询 `forum_members` 的交集；没有交集时返回 404，不创建会话。一方退出后，另一方再打开同一条私聊不会把退出方恢复进来。退出方用新的幂等键再次发起时，重新检查论坛交集；通过后新建一条会话，旧行留给仍在其中的人。原幂等键在调用者已不是活跃成员时返回 404，不恢复成员。
2. 群邀请使用同一条防骚扰规则：被邀请人必须和邀请人同属至少一个论坛。不要求全体成员共享同一个论坛。
3. 新成员的 `joined_position` 为 0，历史接口不按入群位置截断，因此能读入群前的全部文字。
4. 再次加入不把已读游标拨回 0。游标只前进；离开期间的新消息仍算未读，已经读过的位置保持已读。
5. 群人数含群主，默认上限 50，可用 `ODYSSEIA_CONVERSATION_MEMBER_LIMIT` 调低，不能超过数据库里的 50。
6. 每个群同时只有一名群主。群主不能通过退群把群留下；该请求返回 409／`last_manager`。先 `PUT /owner` 转让，才能离开。只剩群主一人时，同样不能退群，只能 `DELETE` 会话来解散。这是论坛 `last_manager` 的同一客户端错误码：操作若会让管理者变为零，就拒绝，并另给一条明确的解散动作。
7. 未读是 `last_position - last_read_position`，只属于该成员。自己发送的消息把自己的游标推到该序号，不给其他成员发已读事件。`conversation.read` 只写入本人的 `inbox:#<user>`。
8. 非成员、已退出成员和已解散的群，读写都返回 404。

没有采用 Stream 的 `hideHistoryBefore`：产品决定新成员看全部历史。没有采用按消息的已读回执：50 人群也不为每条消息写 50 条回执。没有在每条消息上更新 `conversations` 行；列表用最后一条消息的 `created_at`，空会话用创建时间。

## 数据与迁移

第十项迁移 `00010_conversations.sql`：

- `message_streams.kind` 增加 `conversation`。会话从 `last_position = 0` 开始。
- `conversations`：活着的一对一占用 `dm_low < dm_high`；旧槽位释放后这两列为空，历史仍留给未退出的人。`group` 保存 `owner_id` 和标题。创建幂等是 `(created_by, request_id)`。重放只在调用者仍是活跃成员时返回原会话，并锁住会话行；不会清 `removed_at`。
- `conversation_members`：`owner|member`、`joined_position`、`last_read_position`、`removed_at`。
- 群主约束是延迟检查：活着的群恰好有一名未退出的 owner，且等于 `owner_id`。已读游标的触发器拒绝回退。成员数触发器拒绝超过 50。
- Outbox 的 `realtime_publish` 放宽为同时接受 `inbox:#<uuid>`。`scope_id` 仍是会话 ID，因此同一次扇出留在现有的 scope 分区。频道后缀是收件人，不再要求等于 `scope_id`。序号 0 只允许出现在非消息类的 inbox 事件上。

这项迁移不改分区生成，新检查是旧检查的超集，**不要求排空 Outbox**。上线顺序：先迁移，再给 Centrifugo 增加 `inbox` namespace，然后才让 API 写会话。旧消费者若拒绝未知频道，会重试这些新行。

回滚在存在会话行、`kind = conversation` 的流，或 `inbox:` 事件时直接失败，不删数据。P3 的迁移往返测试先卸下第十项，再卸下第八项，然后按相反顺序装回，避免会话外键挡住 `message_streams_id_kind`。

运行身份在原有授权之外需要：

```sql
GRANT SELECT, INSERT ON odysseia.conversations, odysseia.conversation_members TO odysseia_runtime;
GRANT INSERT ON odysseia.message_streams, odysseia.messages TO odysseia_runtime;
GRANT UPDATE (owner_id, dissolved_at, dm_low, dm_high) ON odysseia.conversations TO odysseia_runtime;
GRANT UPDATE (role, joined_position, last_read_position, joined_at, removed_at)
    ON odysseia.conversation_members TO odysseia_runtime;
GRANT UPDATE (last_position) ON odysseia.message_streams TO odysseia_runtime;
GRANT SELECT ON odysseia.users, odysseia.forum_members, odysseia.message_streams, odysseia.messages TO odysseia_runtime;
```

Outbox 的 INSERT 授权不变。第十一项之后还要授予 `attachments` 的 SELECT、INSERT、UPDATE，以及 `message_attachments` 的 SELECT、INSERT。UPDATE 只为了 `FOR UPDATE` 行锁。见 [附件记录](P4图片与语音附件-2026-10-31.md)。

## API 与事件

OpenAPI `info.version` 为 0.7.0。整数序号沿用现有契约，JSON 里是十进制字符串。

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/v1/conversations/dm` | 打开私聊。调用者仍在其中时返回该条，不恢复对方。退出后的原键为 404。新键在仍同属一个论坛时新建一条。 |
| POST | `/v1/conversations/groups` | 创建群，调用者是唯一群主。`member_ids` 顺序不影响幂等摘要。被移出后用原键重放为 404。 |
| GET | `/v1/conversations?after=` | 按最近活动时间倒序。游标绑定当前用户。 |
| GET | `/v1/conversations/{id}` | 含活跃成员。 |
| GET、POST | `/v1/conversations/{id}/messages` | 权威历史与发文字。POST 需要 `Idempotency-Key`。`quote_id` 必须是本会话的消息。 |
| PUT、DELETE | `/v1/conversations/{id}/members/{user_id}` | 群主加人；退出或踢人。群主自退返回 `last_manager`。 |
| PUT | `/v1/conversations/{id}/owner` | 把唯一群主转给一名活跃成员。 |
| PUT | `/v1/conversations/{id}/read` | `{ "position": "<十进制字符串>" }`。更小或相等的序号不改变游标，也不发事件。 |
| DELETE | `/v1/conversations/{id}` | 群主解散。私聊没有解散，参与者自己退出。 |
| GET | `/v1/me/unread` | 只返回未读数大于 0 的会话。 |
| POST | `/v1/me/inbox/subscription` | 返回 `inbox:#<调用者 UUID>`。这是频道名，不是授权。 |

事件类型（信封版本仍为 1，`scope_id` 为会话 ID）：

- `conversation.created`
- `conversation.message.created`
- `conversation.member.added`
- `conversation.member.removed`
- `conversation.read`（仅本人）
- `conversation.owner.changed`
- `conversation.dissolved`

一条文字消息在同一事务里为每个活跃成员插入一行 Outbox，使用 `INSERT … SELECT`。发送人的游标在同一事务里前进，不再另插一条 read，因此该消息的 Outbox 行数等于当时的活跃成员数。Centrifugo 历史只覆盖 namespace 上的短窗口；断线超过该窗口后用 HTTPS 历史补齐。

## 与设计摘要的偏差

- 迁移号是 **00010**。00009 已由协作面的身份组占用。
- 事件名带 `conversation.` 前缀，和 `forum.message.created`、`channel.message.created` 一样，避免和论坛消息混淆。
- 增加了 `conversation.owner.changed`、`conversation.dissolved`，以及 `DELETE /v1/conversations/{id}`。否则转让和解散没有可订阅的结果，最后一位群主也没有对应动作。
- 增加 `POST /v1/me/inbox/subscription`，与论坛／帖子／频道的频道名接口一致。授权仍由 Centrifugo 的用户限定频道完成。
- 列表游标是活动时间和会话 ID，不是帖子那种位置游标。
- 私聊不把已退出的人恢复进旧行。重新开聊是新建一条，并再次检查论坛交集；旧会话的 `dm_low`／`dm_high` 被清空以让出唯一槽。没有单独的重新邀请接口。
- 本刀没有把会话历史放进论坛正文页缓存。成员退出后的下一次读取直接看数据库。
