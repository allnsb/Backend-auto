## 五项修复

| 原审查项 | 修复行为 | 回归证据 |
| --- | --- | --- |
| F1：成员移除提交后，排队发送仍写入 | 会话先取得 stream／conversation 锁，再以独立 READ COMMITTED 语句重新读取成员状态。发送批次中的授权先于幂等重放；管理路径也重新读取当前角色。 | 受限运行身份的真实发送等待数据库锁；移除事务提交后返回 404 对应领域错误，数据库零新增消息。 |
| F2：目录组移除绕过最后管理者 | 目录组分配和移除均保护该用户此前管理的论坛。更高只读组覆盖管理授权也会回滚，返回 409／`last_manager`。目录变更独占控制锁，论坛成员／角色变更共享控制锁后锁论坛；普通消息不取得控制锁。受影响论坛按集合查询，没有逐论坛 SQL 往返。 | 唯一管理者移除被拒绝；分配更高只读组被拒绝且回滚；存在另一管理者时可移除；两名管理者并发移除仅一项成功，另一项拒绝。HTTP 两条目录变更路由的 409 及 Problem 契约通过。 |
| F3：WebM 清理失败返回原文件 | 清理函数返回错误，入口拒绝异常文件；不保留原始字节兜底。继续扫描未知长度 Segment／Cluster 后的元素。 | 带人工坐标的真实 WebM：合法未知长度 Segment 可处理，异常尾部拒绝；未知长度 Cluster 后的 Tags 仍清理。 |
| F4：WebM 清理改变索引偏移 | 参照 Matroska 规范，用等长 Void 替换 Tags、指向 Tags 的 Seek 项及被遍历重写容器的 CRC。不重写容器大小，不移动其它元素，保留 Cues 与有效 Seek 项。 | 真实 FFmpeg 编码样本清理后位置不变、人工坐标消失、调用方输入不变，FFmpeg 解码无错误输出；独立索引探针确认保留的 Info／Tracks／Cues 三项 Seek 均仍指向正确元素，Tags 的 Seek 已移除。 |
| F5：表情管理忽略目录身份组 | 复用协作面的有效身份组解析，取目录组／论坛角色最高者。上传、幂等重放和删除均在事务内取得论坛管理锁后重新授权。全站表情独立 owner 配置规则保留。 | 本地论坛角色为 member、目录角色为 owner 的用户可上传并删除论坛表情。原普通成员拒绝、跨论坛边界和删除投影测试保留。 |

## 参考与取舍

- [PostgreSQL 18 READ COMMITTED](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED)：取得锁后独立语句获取新快照；发送授权仍放在现有 pgx.Batch 中，不为该复查增加一次发送往返。管理操作则在取得锁后另外查询当前角色。
- [PostgreSQL 事务级咨询锁](https://www.postgresql.org/docs/18/functions-admin.html#FUNCTIONS-ADVISORY-LOCKS)：共享／独占协议用于低频管理不变量，按事务释放，不进入消息热路径。
- [RFC 9559 Matroska 编辑规则](https://www.rfc-editor.org/rfc/rfc9559.html)：使用 Void 保留布局，处理 SeekHead 和 CRC。选择现有处理器中的有限结构修复，没有把完整媒体转码服务引入运行时；测试复用真实 FFmpeg 编解码器。
- [Centrifugo 消费错误处理](https://centrifugal.dev/docs/server/consumers#how-consumers-work)：临时错误才重试，其它错误记录并标记已处理。修正文档错误的兜底承诺。

## 升级与剩余边界

本轮没有部署。实际升级时暂停目录身份组／成员／表情的管理写操作，收敛全部 API 节点到同一锁协议后再开放；混跑旧节点时不能保证新增管理不变量。没有新增迁移，不要求为此次修复排空 Outbox。新增 inbox namespace 仍须在任何会话写入前部署到全部消费节点。

以下没有被本轮五项修复自动完成：

- 新会话 inbox 的真实 WSS、跨节点签收／恢复与成员变化验收；既有论坛实时回归通过不能替代它。
- 真实 R2 桶、生命周期和真实 ZITADEL；本轮没有凭据，也没有对真实桶上传／删除。
- 旧 0.5.1 一轮 25 次目标投递缺口仍未定位，P6 全站容量未验收。此次不是容量优化，未声明吞吐增加。
- 附件清理跨网络长事务、上传前并发配额预留和纯论坛启动的媒体配置依赖，仍是待评估事项，不作为已修复问题列出。
- 平台最后管理员保护、管理员访问、生产存储／备份加密、完整高可用及前端实际签收仍需独立完成。

本轮改动集中于会话授权、管理权限、媒体清理及其测试／契约。对象存储仍通过原接口，权限规则集中在 PostgreSQL 适配层的既有有效角色入口；没有为修复拆出新的框架或跨领域接口层。
