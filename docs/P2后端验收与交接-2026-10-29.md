# P2 后端验收与交接

日期：2026-10-29。结论：**当前已批准的独立成员论坛切片，P2 后端 A01–A08 已完成，可进入 P3。** 验收使用合成身份与数据；本结论表示后端功能、真实协议及交接包完成，尚未取得同事前端的实际签收，不是上线许可或完整论坛／IM 的完成声明。

本次 P2 验收时的 HTTP 版本为 0.4.0。后续 0.4.1 增加有界写预算与容量 503／Retry-After，0.4.2 增加按论坛／消息流准入及排队前权限预检查，后续 0.4.3 采用正文页缓存／singleflight、Outbox 逻辑分区／通知和每流等待上限，见 [最新测量与升级边界](缓存分区与准入修复-2026-10-29.md)。0.4.4 的 [同类策略优化](同类社区策略与优化-2026-10-29.md)补独立读批次，有界借用候选未保留。当前 0.4.5 的 [通知锁修复](独立进程压测与通知锁修复-2026-10-29.md)新增第七项迁移、引用批次和单活动写者；依赖不变。成功响应和实时信封保持原字段；下方原验收证据保留时点，所链接 OpenAPI 提供当前契约。

## 本轮新增与重跑

第五项迁移为事务 outbox 增加入队约束及只读聚合视图；独立 realtime-status 命令输出积压量和最老年龄，使用无载荷读取权的观察角色。十类坏命令数据库拒绝、观察角色越权拒绝、真实编译命令的 0→2→0 状态、完整积压与恢复均通过。它不会自动清队列，也没有新增公开诊断端点或发布 worker。

在 backend 目录，以已校验的 Go 和原生实时程序执行：

```powershell
pwsh -File deploy/postgres/test.ps1 -GoExecutable go -TestTags 'integration,realtime,cluster,acceptance' -CentrifugoExecutable '<已校验的centrifugo.exe路径>'
```

acceptance 必须连同前三个标签使用，包含真实 65 秒等待；脚本对 Go 测试设置 180 秒超时。此次 PostgreSQL 包全部集成测试实际用时 78.228 秒。默认回归、全标签 go vet、go mod verify 和六个命令的 Linux／amd64 交叉构建通过；Go／原生实时程序实际在 Windows 执行，数据库与 Valkey 在 Docker Linux 执行，未在 Linux 运行 Go 命令。govulncheck 1.9.0 对全标签含测试调用图未命中当时已知漏洞；不代替原生二进制／镜像完整供应链审计。

测试容器／专用网络与原生子进程已清理；配置、私钥和日志留在忽略且受限的 runtime 目录。没有变更旧项目、上传私密资料或进行生产部署。

## 后续验收账本

P2 的原始 A08 要求是提供后端接入材料；此前将同事前端完整签收、共享缓存高可用和正式容量等统称为 P2“收尾”，容易使阶段范围不断扩大。本次按原 A01–A08 关闭后端切片，并将未执行项显式保留到它们对应的后续交付：

| 后续工作 | 所属阶段与验收门槛 |
|---|---|
| 同事前端页面、登录环境、部署域名／CORS、实际缓冲与恢复签收 | 贯穿 P3 联调并在 P6 上线验收，不声称本轮已实现前端页面。 |
| 即时式帖子、固定频道及作品关联边界 | P3；当前只支持 threaded，同帖引用范围沿用用户批准。 |
| 完整聊天、权限／作品／附件与管理审计 | P4／P5，依产品基线逐项实施。 |
| 持续刷新的既有连接在控制面故障下的正式撤权上限、授权周期复核 | P6 前必须定义并验证；60 秒未刷新测试不代替它。当前异步撤权不能承诺统一故障 SLA。 |
| Valkey 高可用／持久化、数据库重启、跨主机网络分区、小时级积压、乱序注入、坏命令集中告警与处置演练 | P6 故障验收；本轮只有有界 65 秒消费中断，Valkey 仍为单点夹具。 |

未可靠记录逐项人工工时，因此不据代码行数制造新的日历预算；原 24–39 人周仍是待校准估算。P2 证据表明可继续复用原生实时引擎与 SDK，权限、恢复和故障验证占有实质工作量，后续估算应把这些成本与业务 API 开发一并记录。

架构复查：此次变化集中于 PostgreSQL 实时协议约束、观察命令和集成夹具；forum／message 与公开 HTTPS API 没有引入缓存或 SDK 类型。替换实时服务只需调整事件适配和相应协议约束／夹具；移除观察命令或 acceptance 标签后，身份与论坛仍能独立验证。
