## 授权方式调整

核对 [官方订阅代理说明](https://centrifugal.dev/docs/server/proxy)和 [6.10.2 handler 源码](https://github.com/centrifugal/centrifugo/blob/v6.10.2/internal/client/handler.go)后确认：有效频道 JWT 会直接通过，不进入订阅代理。只添加代理和断连动作，仍不能阻止旧频道 JWT 重订阅。因此当前开发契约升级为 info.version=0.4.0：

- 只签发身份连接 JWT，最多 60 秒，且不延长原 Access Token 的 exp；不包含 channel／channels／subs 授权。
- 原 /v1/forums/{forum_id}/subscription-token 和 /v1/topics/{topic_id}/subscription-token 替换为 /subscription，响应只有 channel，未保留旧令牌路径或静默兼容。
- 客户端不带频道 JWT 订阅；forum／topic namespace 启用 subscribe_proxy_enabled，每次初订阅、重新订阅和恢复均经过 HTTPS /_internal/realtime/subscribe，复用 GetForum／GetTopic 的当前读取权限。
- Centrifugo 不配置旧的独立 subscription_token 验签器，API 也不再持有或签发频道密钥。原频道 JWT 及连接 JWT 冒充频道凭据均有拒绝测试。
- 代理使用与连接签名分开的 ODYSSEIA_REALTIME_PROXY_SECRET，通过固定 X-Odysseia-Proxy-Key 传送；客户端 Bearer 不能调用代理。静态凭据不列入 http_headers 或 emulated_headers，避免客户端覆盖。代理到 API 使用 TLS、指定 CA 并校验主机名，没有安装系统信任或关闭验证。
- 代理仅相信受认证的 Centrifugo 请求的 user／channel；data、meta、labels 不提供身份或权限。数据库不可用返回 503，不默认放行；缺少成员与不存在资源均映射到协议拒绝码 103。

前端需按 [当前接入说明](../backend/deploy/realtime/README.md)切换；机器契约见 [OpenAPI](../backend/internal/httpapi/openapi.json)。0.3.0 的频道 JWT 试验记录保留为历史，不再表示当前接入方式。

## 成员移除与审计

新增第四项迁移 forum_member_removals 和独立 remove-forum-member 命令；不因完整身份组算法尚待定就暴露任意成员可调用的管理 API。维护账号执行，API 与消费者均未获得成员修改或审计表权限。

操作包含 operation_id、forum_id、user_id、operator、reason。在目标论坛行锁内检查重复操作，再删除成员、记录实际是否移除，并将 disconnect 写进现有 outbox；任一步失败整体回滚。相同操作 UUID 和内容重试返回原结果，内容冲突明确失败。成员原本不存在时记录 removed=false，仍排入断连以覆盖遗留连接；重试不会重复写入。

断连面向该用户所有实时连接，使用应用码 4001／permissions changed，允许 SDK 重新连接；仍有权限的其他论坛也会短暂重连并重新授权，其他用户不受影响。这是当前简单明确的粒度，未逐帖扫描或逐条调用网络。根据 [Centrifuge 的码段定义](https://github.com/centrifugal/centrifuge/blob/6aed70d42a3f/disconnect.go)使用 4000 段：初试复用了内部 3000，真实 SDK 仅见 EOF；改为正确的应用码后，SDK 与原始 WSS 客户端均确认明确原因，没有将 EOF 或超时算作撤权成功。

operator 是受信维护环境提供的标签，审计行是数据库内的操作记录；它不是已验证的 IdP 管理员身份、不可篡改审计或完整管理员访问体系。完整管理角色、正式审计存储和保留策略后续实施。

## 实际验证

| 场景 | 通过证据 |
|---|---|
| 移除的原子性 | 强制 outbox 插入失败，成员仍存在，操作审计不存在；恢复后重试成功。 |
| 操作并发幂等 | 12 路相同命令仅一条审计、一条逻辑断连命令，所有结果一致；变更理由复用同 ID 被拒绝。 |
| 维护权限 | API 运行身份不能执行移除；消费者仍只读删 outbox，不读取成员或审计表。 |
| 已有连接撤权 | 同一用户两个已建立连接收到 4001／permissions changed；另一个用户的已有连接继续收消息。 |
| 订阅竞争 | 代理已授权但响应暂停时移除成员；迟到响应不能建立订阅或恢复正文访问。 |
| 旧凭据和历史 | 旧连接身份重新订阅论坛／帖子被代理拒绝，旧频道 JWT 与连接 JWT 冒充频道凭据也拒绝；HTTPS 频道描述与历史返回 404。 |
| 消费者暂时不可读 | 临时撤销消费者 outbox SELECT，真实错误被观测；HTTPS 提交仍持久化，恢复授权后按序投递。 |
| 投递成功、确认失败 | 撤销 DELETE，先收到消息，outbox 仍保留；至少两次真实删除失败后恢复授权，重试未重复发布，后续事件正常到达。未用空等待冒充发生重试。 |
| 连接过期 | 原始 WSS 客户端忽略刷新，短期连接仍由服务端按 3005 过期关闭，普通读超时不算成功。 |

既有 TLS、身份、独立论坛、同帖引用、分页、并发与回滚、SDK 恢复／缓存外加载、HTTPS 响应契约均保留。默认及 integration,realtime 测试通过；go vet、go mod verify、五个命令的 Linux／amd64 交叉构建通过，未在 Linux 实际运行。govulncheck v1.9.0 扫描包含测试的完整调用图，未命中当时已知漏洞；不覆盖原生服务的完整供应链审计，也不等于零漏洞保证。

## 时效与剩余边界

数据库提交后新授权请求立即读取当前成员；提交前已经通过的在途 HTTP 操作仍按已有切片边界处理。主动断连是 outbox 消费后的异步动作，维护命令成功表示提交并排队，不表示所有节点和客户端已经确认离开。消费者积压或故障时存在窗口，连接凭据到期仍提供兜底；不能承诺提交瞬间没有任何在途事件。

当前仅验证单节点内存引擎、单分区和短期幂等缓存窗口。跨重启／跨节点／超过缓存期的重复仍须客户端按事件 ID 去重；乱序、长时间积压、不可重试坏命令监控与处置、三万在线容量和正式撤权 SLA 未验收。真实 IdP 会话撤销、作品与完整聊天、存储／备份加密、密钥管理及管理员审计也未完成。P2 仍需完整前端联调和后续故障验收，不据此开始生产部署。

本轮纯 forum 类型只新增维护命令及校验；PostgreSQL 拥有事务与审计，供应商断连载荷仍在 forum_events.go，HTTP 拥有协议／服务身份，realtime 只签发连接凭据。替换实时组件无需改变论坛正文规则；移除维护命令或实时路由不妨碍论坛、身份单独验证，没有新增通用插件层或每表接口。
