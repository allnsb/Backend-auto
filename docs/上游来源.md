源码位于 `services/bbs-go`、`services/mongooseim`、`services/tinode` 与 `services/open-im-server`。两套新候选的标签与当前 HEAD 已核对，工作区干净；最初 BBS-GO／OpenIM 获取阶段的 Git 完整性校验仍保留。各次验证范围见 [版本锁定文件](../upstreams.lock.json)，不能将旧仓库的校验记录套用给新增仓库。

仓库使用固定标签的浅克隆；OpenIM 使用附注标签，表中记录其最终解析的 commit，而不是标签对象 SHA。后续改造前从固定提交建立开发分支，需要历史时再补取。

BBS-GO 与 Tinode 保留 GPLv3 LICENSE；MongooseIM 保留 GPLv2 COPYING 及其中的 OpenSSL 链接例外；旧 OpenIM 服务端保留 Apache 2.0 LICENSE。SDK、成品客户端与商业功能分别核对。候选试验配置及手写协议客户端独立放在 `deploy/im-trials/`，不据此声称上游或正式 SDK 已完成需求适配。

源码获取阶段只完成 Git 完整性校验。随后在 2026-10-26 进行首轮[源码审查](源码审查与可行性评估-2026-10-26.md)，准备 E 盘便携 Go 与隔离依赖缓存，运行了 BBS-GO 选定后端测试及独立约束用例；该阶段未启动服务。后续两套 IM 的隔离本地试验结果独立记录，不将原生协议验证等同于业务集成或生产容量验收。

BBS-GO 的 go.mod 声明 Go 1.26.0，OpenIM 为 Go 1.25.0；本次本地测试实际使用官方 Go 1.27.3 Windows/amd64，工具链来源与摘要记录在审查材料中，不代表正式生产工具链已定。

试验部署入口为 [deploy/im-trials](../deploy/im-trials/README.md)，结果见 [IM 候选本地试验记录](IM候选本地试验结果-2026-10-26.md)。MongooseIM 从固定源码构建；Tinode 使用固定发行版镜像，实际 tag／digest 与运行证据另记。源码 commit 不自动证明镜像内二进制的构建来源一致；生产构建、完整兼容性与容量均需单独验收。
