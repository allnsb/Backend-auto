# P4 前端接入与恢复契约

兼容更新：P5-a 将总 API 版本提升为 0.10.0；本文件的 P4 路径和实时事件语义保持。作品私有草稿不发送 inbox 事件，接入见 [P5-a 契约](P5-a作品私有草稿-2026-11-01.md)。

更新时间：2026-11-01。适用：HTTP 0.9.1／事件版本 1／十三项迁移。当前约定范围是私聊群聊、私人未读、会话图片／语音与七天清理、全站／论坛表情。机器契约以 [OpenAPI](../backend/internal/httpapi/openapi.json) 为准，测试证据见 [P4 收尾记录](P4后端验收与交接-2026-11-01.md)。

## 身份与个人收件箱

1. 用访问令牌调用 HTTPS `GET /v1/me`，首次有效访问会引导本地账号。不要用身份系统的 subject 代替本地 UUID。
2. HTTPS `POST /v1/realtime/connection-token` 取得连接 JWT 和 `expires_at`；HTTPS `POST /v1/me/inbox/subscription` 取得频道名 `inbox:#<本地 UUID>`。
3. 通过 WSS 连接并订阅返回的频道。频道名不是授权；Centrifugo 根据连接 JWT 中的本地用户 ID 检查用户限定频道。客户端不能读他人的收件箱，也不能直接 publish 消息。
4. 使用连接 JWT 到期时间刷新；新连接令牌的有效期不会超过原访问令牌。访问令牌到期时重新走身份系统登录／刷新，不通过不断请求连接令牌延长失效身份。

所有写入走 HTTPS 业务接口。消息发送需要 UUID 格式的 `Idempotency-Key`；超时后重试相同正文和相同键。409 表示同键不同内容，503 的 `Retry-After` 用于有界重试。不要把新的键用于一次结果未知的重复发送。

## 消息和事件的身份

| 字段 | 含义 | 用法 |
| --- | --- | --- |
| `event.id` | 稳定事件 ID；消费重试和恢复保持它 | 防止同一事件重复应用。 |
| `scope_id` | 事件所属会话 UUID | 路由到对应会话。 |
| `position` | 该会话的业务位置，JSON 十进制字符串 | 消息类与 message.sequence 对应；管理事件可与消息同位置，创建事件可为 0。 |
| `data.id`，消息类 | 持久化消息 UUID | 合并 HTTPS 发送结果、历史页和 WSS 重放，避免显示重复消息。 |
| WSS `offset`、`epoch` | 整个个人收件箱的实时流位置 | 只用于该收件箱恢复，不能拿来比较不同会话的消息序号。 |

个人收件箱混合多个会话；不能给全站或整个收件箱维护一个“最大消息 sequence”来过滤事件。控制事件即使 `position` 没有增加，也可能代表加人、踢人或转让，必须按事件 ID 处理。大整数序号在前端保留字符串或使用 BigInt。

## 七类事件

信封共同字段为 `id`、`version: 1`、`type`、`scope_id`、`position`、`data`。

| type | data | 接收范围与动作 |
| --- | --- | --- |
| `conversation.created` | id、kind、可选 title／owner_id、created_by、member_ids | 当前活跃成员；刷新会话详情和列表。 |
| `conversation.message.created` | Message：id、stream_id、sequence、author_id、body、quote_id、attachments、emojis、created_at | 当时的活跃成员，含发送人；按消息 ID 合并。 |
| `conversation.member.added` | user_id、role | 当前成员，含新增成员；新成员可看全部历史。 |
| `conversation.member.removed` | user_id、role | 剩余成员与被移除者；本人被移除时关闭该会话的读写入口，随后 HTTPS 返回 404。 |
| `conversation.read` | position | 只发给本人各设备；更新个人水位。没有他人的已读回执。 |
| `conversation.owner.changed` | owner_id | 当前成员；刷新管理操作入口。 |
| `conversation.dissolved` | id | 解散时的活跃成员；关闭会话，随后 HTTPS 返回 404。 |

被踢出一个群不会关闭整个个人收件箱，其他私聊／群聊仍可用。收件箱缓存可能包含曾经合法收到的旧消息；撤权后的 HTTPS 不再授权读取，新的群消息不再投递。服务器无法抹掉客户端已经保存的副本。

## 正常恢复和缓存缺口

部署示例的个人收件箱缓存是 **64 个事件、最多 60 秒**，同时受条数和时间约束；这是所有会话共用的一个用户流，不是每个群各 64 条，也不代表离线 60 秒内必定可恢复。

- `Recovered=true`：按事件 ID／消息 ID 应用重放，继续实时接收。
- `Recovered=false`：继续订阅并暂存新事件，然后通过 HTTPS 重新加载当前可见会话列表、详情、未读和消息历史。历史按 `next` 游标继续，不能只取第一页。
- 缓冲事件与历史重叠时按消息 ID 合并；管理事件按事件 ID 处理。缓冲区必须有界，溢出后重新同步，不能悄悄丢弃。
- 会话列表分页完毕后，再刷新同步期间发生事件的会话；未知 `scope_id` 先 GET 详情，404 表示当前无权访问。目录扫描结束前不要仅凭某一页缺少某个会话就删除本地状态。
- 缓存失效期间可能发生踢出／解散，不能只补消息正文：旧本地会话必须与完整的当前授权列表核对，404 关闭入口。

本轮真实协议测试覆盖跨节点、节点重启、离线移除、确认失败重试，以及超出缓存后 72 条消息／5 页历史与实时重叠合并。前端页面本身尚未签收。

### Go SDK 的 GetState 陷阱

`centrifuge-go v0.13.0` 的 `GetState` 是重新加载应用状态的回调。它收到服务器 112（无法恢复位置）后会再次调用；把旧 offset／epoch 写成永不变化的常量，会造成反复重试。

普通客户端重连可由 SDK 保留流位置；失败时按上述 `Recovered=false` 流程补读。使用 `GetState` 时，应遵守 SDK 的“先读实时位置，再读权威状态”顺序，并返回刷新后的匹配位置。当前业务 API 没有提供服务端收件箱快照位置接口，不能把会话消息 sequence 当作替代值；新页面可先建立实时订阅，再加载 HTTPS 状态。

参考：[用户限定频道](https://centrifugal.dev/docs/server/channels#user-channel-boundary)、[历史和恢复](https://centrifugal.dev/docs/server/history_and_recovery)、[固定版本 SDK SubscriptionConfig](https://pkg.go.dev/github.com/centrifugal/centrifuge-go@v0.13.0#SubscriptionConfig)。

## 附件与表情

- 图片／语音先上传到会话附件接口，再把 `attachment_ids` 放进消息；带附件时正文可空。WSS 只带附件元数据，不带对象键或预签名 URL。
- 下载时重新请求受成员权限保护的 HTTPS 附件接口，再跟随 302。短期签名 URL 是临时访问凭据，不写入永久消息／日志。
- 附件默认从上传起约七天过期。下载 404 或历史中的 `expired=true` 应显示已过期；空正文消息及附件链接仍在。此前缓存的实时元数据可能尚未标记过期，以新的授权 HTTPS 读取为准。
- 表情图片来自独立公开桶。论坛表情仅同论坛使用，私聊群聊只接受全站表情。目录软删除后，新的 HTTPS 读取降为 `:name:`；公开图片的不可变缓存不承担彻底撤回。
- 公开表情不能承载私密附件，私人图片／语音不能放进公开表情桶。
