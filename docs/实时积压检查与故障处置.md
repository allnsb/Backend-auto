# 实时积压检查与故障处置

日期：2026-10-29。用于当前 0.4.5 后端切片，完整收尾证据见 [P2 验收](P2后端验收与交接-2026-10-29.md)。本说明提供可运行诊断和明确处置顺序；生产告警接收、值班和容量阈值在 P6 接入。

## 只读检查

当前共七项迁移；第七项移除逐条 NOTIFY，依赖已有五分区／20ms 轮询且不改变积压或路由。第六项要求停写、排空并同步切换全部消费者，必须按 [升级步骤](../backend/deploy/realtime/README.md)执行。第五项迁移增加 outbox 命令约束和聚合视图 realtime_backlog；迁移会核查现有待投递记录，历史异常数据会使迁移明确失败，不自动删除或跳过。运行身份仍不能迁移。

部署时显式准备独立非超级用户观察角色；只授予连接目标库、schema USAGE 和聚合视图 SELECT。下面的角色名是夹具示例，不在业务迁移中创建部署账号：

```sql
GRANT CONNECT ON DATABASE odysseia_cluster_test TO odysseia_observer;
GRANT USAGE ON SCHEMA odysseia TO odysseia_observer;
GRANT SELECT ON odysseia.realtime_backlog TO odysseia_observer;
```

视图由其所有者读取底表，只返回 pending、publications、disconnects、oldest_created_at、oldest_age_seconds；观察角色没有 outbox／用户／正文表读取或删除权限。实际越权 SELECT 和 DELETE 已被数据库拒绝。

在进程环境提供 ODYSSEIA_OBSERVER_DATABASE_URL（verify-full 与 CA 路径）和可选 ODYSSEIA_BACKLOG_WARN_AFTER，运行编译后的 realtime-status。开发时可 go run ./cmd/realtime-status 查看 JSON，但自动化应调用编译产物，以保留程序的准确退出码。

| 程序退出码 | 语义 |
|---|---|
| 0 | 最老积压未超过配置阈值，status=within_threshold。空队列也返回此状态，不证明消费者、broker 或客户端均健康。 |
| 2 | 队列非空且最老积压达到阈值，status=backlog_age_exceeded；JSON 保留可供处理的聚合数量和年龄。 |
| 1 | 配置、连接、查询或输出失败。不能将查询失败解释为空队列。 |

默认警戒值为 30 秒，是工程起点，不是生产投递／撤权 SLA。命令只读，不确认消费、不清理、不重放，也不输出用户 ID、载荷、正文或凭据。P6 应结合原生节点存活、broker 健康与消费者日志设定正式告警，不能只看队列是否为零。

## 根据现象处置

| 现象 | 处理 |
|---|---|
| 两次检查间数量／年龄增加 | 检查原生服务是否运行、TLS／证书、数据库消费者权限、broker 连接和同名同分区配置；保留 outbox，让恢复后的原生消费者继续处理。 |
| error processing postgresql outbox | 区分数据库连接、SELECT、DELETE 和提交错误；修复对应依赖或授权，再观察年龄回落和队列排空。DELETE 失败意味着可能已经广播，禁止据此再次写入正文。 |
| error processing consumed event | 原生分发暂时失败可能阻塞后续命令；检查 broker 和服务端错误，保留事件 ID／幂等键，不批量手删队列绕过故障。 |
| non retryable error during consuming, skip message | 立即按协议／配置异常处理。该消息可能被原生消费者从队列移除，队列为零不能证明投递成功；检查 namespace、命令格式及版本是否与当前生产者一致。 |
| 队列含 disconnect 且年龄增长 | 成员变化已经提交，但主动断连可能尚未执行；先恢复控制面消费，并验证目标连接／重新订阅的拒绝。HTTPS 正文与历史仍按当前成员关系拒绝。 |
| Outbox 为零但接收端有缺口 | 保留原生服务错误、SDK 连接／订阅／恢复标志及缺失位置，核对当前授权 HTTPS 历史。实时接收和补读分别计量；不能据队列为零宣称签收，或通过重新发业务请求重建正文。原版长时测试的一轮 25 次目标缺口仍未定位，见 [整体对照](整体优化与写预算对照-2026-10-30.md)。 |

永久错误的行为由固定版本 [dispatcher](https://github.com/centrifugal/centrifugo/blob/v6.10.2/internal/api/consuming.go)和 [PostgreSQL 消费器](https://github.com/centrifugal/centrifugo/blob/v6.10.2/internal/consuming/postgresql.go)核实。日志仅记录错误与方法，不将载荷作为故障说明复制到聊天或公开告警。

第五项迁移在事务提交前拒绝不支持的方法／分区、缺失关键字段、频道与作用域不一致、错误事件幂等键及不正确的断连命令；十类真实数据库负例已验证。它防止当前生产者明显不合法的命令入队，不能覆盖实时服务的配置漂移或所有永久错误。第六项现将分区改为数据库生成的控制 0／数据 1–4，并保留信封约束；显式覆盖分区被拒绝。新增频道类型、事件版本或再次调整分区前必须同步变更此适配边界。

正文持久化成功而实时提示遗漏时，客户端走当前有权的 HTTPS 补读／重订阅流程，按消息 ID 和事件 ID 合并。不能通过再发一次业务请求“补事件”；已有幂等请求仅返回原结果，也不保证重新发布原事件。本切片没有提供人工任意重放／丢弃接口。事故中需要定向重放时，应先形成保留原 ID 的受审操作方案，不直接手改线上正文。

## 撤权与恢复边界

健康本机双节点的三个连接以 3 秒回归预算验证主动断连；这是测试预算，不是生产 P95／P99。消费者阻塞时，主动断连受队列延迟影响，未刷新身份凭据的连接仍按真实 60 秒凭据到期关闭，客户端新订阅和 HTTPS 请求检查当前成员。

身份连接凭据的刷新本身不重新检查该连接已持有的全部频道。故障期间，持续刷新的已有连接不能仅靠“60 秒 JWT”推导出统一的撤权上限；需要按生产目标验证授权定时复核及控制面故障处理。该项与正式 SLA 一起保留为 P6 上线门槛。不要把本轮未刷新客户端的过期测试扩大成所有客户端的硬时限。

共享缓存消失或历史过期时，Recovered=false 必须触发授权 HTTPS 补读。短期幂等状态丢失后允许事件重放；合并以稳定事件 ID、消息 ID 和业务 sequence 为准，WSS offset 不充当业务分页游标。当前只支持创建事件，编辑／删除另需变更同步契约。
