# P5-a：作者私有作品草稿

日期：2026-11-01。当前 HTTP **0.10.0**／**十四项迁移**。P4 按已约定的本地后端范围保持收尾；本轮只是 P5 的首个工程切片，**P5 整体未完成，P6 容量未验收**。

## 范围与依据

用户要求继续推进。公开发布、资源格式／限额、作者与平台权限覆盖、R18 发现和旧链接规则仍待定，先按保守的工程边界验证作者私有草稿：创建、读取、列表、修改。这不是用户已确认的完整作品权限政策；没有新批准记录时，不能把本切片的作者独占规则固化为未来的平台管理规则。

作品不要求关联论坛、帖子或频道；数据库没有这些外键，forum/message 核心也不依赖 work。纯 `internal/work` 只维护输入规则与数据类型；HTTP 负责认证、格式与响应；PostgreSQL 适配负责作者条件、幂等和并发更新。进程入口将共享写预算显式注入两类存储。没有新增第三方依赖、升级既有锁或移植外部源码。

本轮不实现发布／下架、文件／下载、资源版本、作品与论坛关联、标签／搜索、R18 分类、作者／平台覆盖、草稿删除和实时草稿通知。不存在公开作品列表。草稿内容不进入论坛或个人 inbox 的 Outbox。

## 复用与取舍

- [Strapi Draft & Publish](https://docs.strapi.io/cms/features/draft-and-publish)：参考草稿与已发布内容分开的产品思路，本轮仅支持草稿，不引入 CMS 或复制其代码。
- [PostgreSQL 18 UPDATE](https://www.postgresql.org/docs/18/sql-update.html)：使用 `WHERE author_id AND revision` 与 `RETURNING` 原子判断更新；并发正确性由数据库保证，本地排队只减少争用。
- [RFC 9110 If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)：评估条件更新。本轮沿用 JSON 响应与统一 Problem 错误，明确要求请求携带 `revision`、冲突返回 409；没有声称实现 ETag／If-Match、通配符或 412 语义。
- 复用现有 UUID、pgx、显式迁移、认证、Problem、组合游标和有界写准入。公开作品的缓存与物理分区没有当前证据，不因“扩展性”预先加入。

## HTTPS 接口契约

所有接口需要有效 Access Token；响应 `Cache-Control: no-store`。调用者来自认证，拒绝输入 `author_id`、`status` 等未知字段。完整契约为 [OpenAPI](../backend/internal/httpapi/openapi.json)。正文为纯文本，客户端必须按文本渲染或在自己的富文本边界清理，不能直接当 HTML 插入。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /v1/works` | UUID `Idempotency-Key` 必填；输入 `title`、可选 `introduction`。首次 201，精确重放 200；同作者／键但原始内容不同返回 409 `idempotency_conflict`。响应 Location 指向作品。 |
| `GET /v1/works/{work_id}` | 只有作者可读。不存在或非作者均 404，即使调用者是目录 owner；不暴露他人草稿的存在。 |
| `GET /v1/me/works` | 仅自己的草稿，`limit` 默认 50／最大 100；`after` 为 `next`。固定 `(created_at,id)` 降序 seek，修改不改变顺序；末页没有 next，空列表为 `[]`。 |
| `PUT /v1/works/{work_id}` | 输入完整 `title`、可选 `introduction`、上次读取的 `revision`。省略 introduction 表示清空。陈旧 revision 返回 409 `work_revision_conflict`，需重新读取后合并。 |

`revision` 是正 int64 的十进制 JSON **字符串**，例如 `"1"`；防止前端数字精度丢失。它用于并发控制，不是发布资源版本，也没有历史归档。当前 revision 与内容完全相同时是真正的无操作：revision、updated_at 都不改变。不同内容提交成功才递增 revision。创建时保存的请求哈希不随编辑变化，原创建请求重放返回**当前**草稿，不能把它当作恢复第一版正文的接口。

标题 1–200 个 Unicode 码点、无首尾空白；介绍最多 32768 个 UTF-8 字节，可为空。两者禁止 NUL。这些是首轮工程输入上限，不是已确认的收费／作品配额。HTTP JSON 请求仍受现有 256 KiB 总请求体上限约束。游标绑定集合与作者，Base64 只是编码；授权始终由数据库作者条件执行，不能把游标当签名凭据。

## 数据、部署与写预算

第十四项 [迁移](../backend/internal/postgres/migrations/00014_private_work_drafts.sql)增加 `works`：固定 draft 状态、作者与创建请求唯一键、不可随更新改写的创建哈希、正 revision、作者／创建时间索引。没有改已有十三项迁移、Outbox 路由或消费协议；本次不要求 Outbox 排空，但显式迁移和授权必须先于新版 API 启动。

运行角色的新增最小授权：

```sql
GRANT SELECT, INSERT ON odysseia.works TO odysseia_runtime;
GRANT UPDATE (title, introduction, revision, updated_at)
    ON odysseia.works TO odysseia_runtime;
```

不授予 DELETE、作者／状态／请求哈希的 UPDATE 或 schema 创建权。角色名按正式部署替换，在 [上线清单 L02](正式上线待填与验收清单.md)签收。有草稿数据时 Down 明确拒绝删表；应先保留数据和评估兼容回退，不能为降版本直接销毁草稿。

API 入口只创建一个 WriteBudget，论坛／频道／会话消息与作品草稿存储复用；默认池 16 → 10 个写名额，仍为每进程 256 个活动／等待命令、每作用域 12 个、最长等 2 秒。作品创建以作者、编辑以作品作为独立命名空间；相同 UUID 不会与论坛／消息流混淆。不同 API 实例各有本地预算，数据库条件负责跨实例正确性。该预算没有隔离身份查询、权限预查或保留专用读连接，不能据此声称消除了池争用或证明生产容量。管理与附件路径的既有预算边界没有扩大声明。

本轮无新增配置字段；`ODYSSEIA_MAX_WRITE_TRANSACTIONS` 的说明更新为消息与草稿存储共享。新增有界 `work_draft_write` 计量包含准入后的 SQL 及必要补读，也包含隐式连接获取，不能当作纯 SQL 或提交耗时。未缓存可编辑草稿，无需借用追加型消息缓存的失效假设。
