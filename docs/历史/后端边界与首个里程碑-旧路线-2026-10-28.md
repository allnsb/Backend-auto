# 后端边界与首个里程碑

本文件保存此前路线的实施草案。2026-10-28 用户要求从头选型，下述 BBS-GO／独立 IM 分工不再是当前固定约束；新方案确定后再更新具体里程碑。当前评估见 [后端独立选型](../../../research/backend-selection-independent-2026-10-28.md)。

历史上曾选择保留 BBS-GO、替换 OpenIM，并行隔离试验 MongooseIM 与 Tinode。旧源码和结果保留，候选原生协议可用不等于下述业务集成已完成。

## 服务职责

| 部分 | 负责 |
|---|---|
| BBS-GO 扩展 | 作品、分类、资源版本、帖子、主楼层、一层子回复、引用、身份组和管理接口 |
| 独立 IM 后端（MongooseIM／Tinode 待选） | 卡内聊天频道、私聊群聊、IM 历史、离线和多端同步；按候选实际验证结果确定接入 |
| 对象存储 | 文件内容；资源归属与下载策略由内容业务控制 |
| 论坛实时事件 | 向实际订阅者推送内容变化，配合 API 游标补拉；具体实现待验证 |

## 第一个可联调流程

1. 先按 [共用验收契约](../IM候选试验验收契约.md) 完成两候选原生协议与权限边界验证，记录功能缺口，再确认 IM 选型。
2. 建立一个业务用户，并映射到选定 IM 后端；在可信入口统一身份和作品权限。
3. 创建一张卡、一个资源版本及一个聊天频道。
4. 发帖者在卡内创建帖子时选择贴吧式或即时式；贴吧式主楼层与子回复只收纳一层，具体引用目标另存。
5. 按帖子选择的模式读取讨论并收到即时变化；个人自由切换视图为期望增强，首发范围待定。两种读取方式应保留同一帖子内容的权威归属，避免正文双写。
6. 验证作者范围、平台覆盖和已有连接撤权后的正文／引用／下载访问。
7. 给前端同事提供接口说明、示例响应、事件格式和测试身份。

## 初期应固定的边界

- 稳定的用户、作品、帖子 ID 与 IM 用户映射。
- 帖子及回复的作品归属、根楼层归属与引用目标。
- 业务正文与聊天正文的权威来源。
- 业务权限向 IM 成员／会话权限的映射与撤权时效；不直接把候选原生角色当成完整 DC 身份组。
- HTTPS／WSS 的公网接入边界。
- 所有原有内容接口也执行作品范围权限。
- 两候选及新路线配置、容器名和数据目录与旧 OpenIM、NodeBB 数据隔离。

发帖者创建单帖时选模式已确认。身份组冲突算法、发布后模式变更、个人切换视图的首发范围、文件规格和保留期限等待定项，不能直接采用上游默认值作为用户要求。
